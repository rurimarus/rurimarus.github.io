# えしりとり 仕様書

## 0. この仕様書について

本仕様書は、サークル制作作品「えしりとり」の開発方針・機能・画面・データ・API・スケジュールをまとめたものです。  
GitHub 上では `siyo.md` として管理。
この仕様書はCopilotによって作成されました。

本作品では、技術スタックをできるだけ増やさず、JavaScript 中心の最小構成で開発します。

> [!IMPORTANT]
> この仕様書の最重要方針は、**少ない技術で確実に完成させること**です。  
> 便利な技術を追加する判断は、まず MVP が動いてから行います。

---

## 1. 企画概要

### 1.1 作品名

**えしりとり**

### 1.2 概要

「えしりとり」は、プレイヤーと AI が交互に絵を描きながら、しりとりを進める Web ゲームです。

プレイヤーは iPad などのブラウザ上で絵を描きます。  
描いた絵は Windows PC 上のサーバーに送信され、AI によって「何の絵に見えるか」を判別されます。

このゲームでは、プレイヤーが何を描いたつもりだったかだけでなく、**AI がその絵をどう認識したか**を重視します。  
そのため、しりとりの進行には、原則として AI の判別結果を優先して使用します。

例：

```text
プレイヤーが「りんご」のつもりで絵を描く
↓
AI が「トマト」と判別する
↓
採用単語は「トマト」になる
↓
次は「と」から始まる単語へ進む
```

> [!IMPORTANT]
> 本作品の売りは「AI が正しく当てること」ではなく、**AI の認識によってしりとりがズレていくこと**です。  
> AI の誤判定は失敗ではなく、ゲーム体験の一部として扱います。

## 5. システム構成

### 5.1 基本構成

```text
iPad ブラウザ
  ↓
HTML / CSS / JavaScript
  ↓
Windows PC 上の Node.js + Express サーバー
  ↓
SQLite
  ↓
外部 AI API
```

### 5.2 基本処理の流れ

```text
1. iPad で Web ページを開く
2. プレイヤーが Canvas に絵を描く
3. JavaScript で画像化する
4. Node.js / Express サーバーへ画像を送信する
5. サーバー側で画像を保存する
6. AI API で画像を判別する
7. AI 認識演出画面を表示する
8. AI 判別結果を優先して採用単語を決める
9. 採用単語の最後の文字から、次のしりとり単語を決める
10. AI 画像生成 API で次の単語の線画を生成する
11. 「絵を描いています...」画面を表示する
12. AI 画像を表示する
13. 進行バーを更新する
14. 5セット繰り返す
15. 結果を確認する
```

## 7. しりとりルール

### 7.1 基本ルール

```text
前の単語の最後の文字から始まる単語を選ぶ
「ん」で終わる単語は使わない
過去に使った単語は使わない
絵にしやすい単語を使う
ひらがなの名詞を使う
不適切な単語は使わない
```

### 7.2 例

```text
りんご
↓
ごりら
↓
らっぱ
↓
ぱんだ
```

### 7.3 濁点・半濁点の扱い

しりとりが詰まりやすい場合は、濁点・半濁点をゆるく扱うことを検討します。

例：

```text
ご → こ
ぱ → は
だ → た
```

ただし、最初の実装では単語リスト側で調整し、複雑な文字変換は後回しにします。

## 8.6 AI認識演出画面

> [!IMPORTANT]
> この画面はクイズ画面ではなく、**AI が画像をどう見ているかを来場者に見せるための演出画面**です。  
> AI の本当の内部思考を表示するのではなく、AI の認識候補・特徴・迷いを、短い吹き出しとして表現します。

### 目的

プレイヤーが描いた画像を AI が判別する間、来場者に「AI が何を見て、何に迷っているか」を分かりやすく見せます。

### 画面構成

画面中央上部に以下を表示します。

```text
AIが考え中...
```

その下の中央に、大きな `？` を表示します。

中央の `？` の背景には、明るくやわらかいグラデーションを配置します。  
雰囲気は、わたあめのような軽い色味にします。

```text
薄いピンク
薄い水色
薄い黄色
薄い紫
```

中央の `？` は白色にします。

### 吹き出し表示

中央の `？` の周囲に、AI の認識候補や特徴を吹き出しとして表示します。

吹き出しは、1〜2秒ごとに1つずつ追加表示します。

例：

```text
オレンジ色で丸い...
これは、みかん？
にんじんにも見える？
果物っぽいかも...
丸いものかな...
```

### 吹き出しデザイン

```text
背景：薄いオレンジ、クリーム色、薄い水色など
角：丸くする
文字色：黒または濃いグレー
表示位置：中央の？の周囲
表示方法：1〜2秒ごとに1つずつ追加
```

### 表示タイミング例

```text
0.0秒：AIが考え中... を表示
0.3秒：中央に？を表示
1.0秒：吹き出し1つ目
2.2秒：吹き出し2つ目
3.4秒：吹き出し3つ目
4.6秒：吹き出し4つ目
5.8秒：吹き出し5つ目
7.0秒：絵を描いています... 画面へ切り替え
```

実装では `setTimeout()` などを使い、固定タイミングで順番に表示してよいです。

## 10. AI画像判別仕様

## 10.1 基本方針

AI画像判別は、まず外部 AI API を使います。

AI は、単語1つだけではなく、AI認識演出画面で使う短い吹き出し文も返します。

ただし、将来的には以下の方式を追加できるようにします。

```text
候補リスト判別
↓
一致率が低い場合だけ API 判別
```

---

## 10.2 最初の実装方針

> [!IMPORTANT]
> しりとり進行では、原則として**プレイヤー入力ではなく AI 判別結果を優先**します。  
> プレイヤー入力は「本人の意図」として保存し、AI 判別とのズレを見せるために使います。

MVP 段階では、プレイヤー入力を保存しつつ、ゲーム進行には AI 判別結果を優先して使用します。

例：

```text
プレイヤー入力：りんご
AI判別：トマト
採用単語：トマト
```

このように、AI が誤判定した場合でも、その誤判定をゲームの失敗とは扱いません。

むしろ、AI の認識によってしりとりが予想外の方向へ進むことを、このゲームの特徴とします。

---

## 10.3 なぜ AI 判別結果を優先するか

このゲームでは、プレイヤーが何を描いたつもりだったかよりも、**AI がその絵を何として認識したか**をゲーム進行に反映します。

そのため、しりとりに使う採用単語は、原則として AI 判別結果を優先します。

例：

```text
プレイヤー入力：りんご
AI判別：トマト
採用単語：トマト
```

この場合、次のしりとりは「りんご」ではなく、AI が判別した「トマト」の最後の文字から進行します。

```text
トマト
↓
とけい
↓
いぬ
```

この仕様により、プレイヤーの意図と AI の認識がズレた場合、そのズレがそのままゲーム展開に影響します。

このズレこそが本ゲームの面白さであり、  
「人間はこう描いたつもりだったが、AI にはこう見えた」  
という認識の違いを楽しむことができます。

## 10.4 AI出力 JSON 仕様

AI には、画像判別結果を JSON 形式で返させます。

### 目的

```text
AI認識演出画面で使う吹き出しを取得する
候補単語を保存する
最終判別結果を保存する
しりとりに使う採用単語を決める
```

### JSON 形式

```json
{
  "thoughtBubbles": [
    "丸い形をしている...",
    "オレンジ色っぽい？",
    "これは、みかん？",
    "にんじんにも少し見える...",
    "果物かもしれない"
  ],
  "candidates": [
    {
      "word": "みかん",
      "confidence": 0.52
    },
    {
      "word": "にんじん",
      "confidence": 0.28
    },
    {
      "word": "ぼーる",
      "confidence": 0.13
    }
  ],
  "finalAnswer": "みかん"
}
```

### 各項目の意味

| 項目 | 内容 |
|---|---|
| `thoughtBubbles` | AI認識演出画面で表示する短い吹き出し文 |
| `candidates` | AIが候補として考えた単語一覧 |
| `word` | 候補単語 |
| `confidence` | AIがその候補らしいと考えた度合い |
| `finalAnswer` | AIの最終判別結果。原則として採用単語になる |

---

## 10.5 採用単語の優先順位

採用単語は、以下の優先順位で決定します。

```text
1. AI の finalAnswer
2. AI candidates の中で使える単語
3. 候補リスト判別結果
4. プレイヤー入力
```

ただし、AI 判別結果がそのまま使えない場合は、候補リスト判別結果またはプレイヤー入力に fallback します。

---

## 10.6 fallback 条件

> [!WARNING]
> AI 判別を優先する方針でも、ゲームが破綻する単語は採用しません。  
> 特に「ん」で終わる単語、文章形式の回答、不適切な単語は fallback 対象です。

AI 判別結果が以下に当てはまる場合、そのまま採用しません。

```text
判別不能
空文字
文章になっている
名詞ではない
ひらがな化できない
「ん」で終わる
不適切な単語
長すぎる単語
意味不明な単語
```

### fallback 例1：「ん」で終わる場合

```text
プレイヤー入力：くだもの
AI判別：みかん
```

AI 判別結果の「みかん」は「ん」で終わるため、しりとりに採用しません。

この場合は、以下の順で代替します。

```text
AI candidates の中で使える単語
↓
候補リスト判別結果
↓
プレイヤー入力
↓
再判別または再入力
```

### fallback 例2：文章になっている場合

```text
AI判別：これは赤い丸のような絵です
```

この場合は単語として使えないため、再判別または整形を行います。

## 10.7 AI判別プロンプト例

```text
この画像が何を描いたものに見えるか判別してください。

ただし、最終回答だけでなく、画面演出として使う短い吹き出し文も作成してください。

条件：
- 吹き出し文は5個程度
- 吹き出し文は短くする
- 「〜かも」「これは、〇〇？」のように迷っている感じにする
- 最終回答は、ひらがなの名詞1語にする
- 「ん」で終わる単語は避ける
- 長音「ー」を含む単語はできるだけ避ける
- 不適切な単語は避ける
- JSONのみで返す

形式：
{
  "thoughtBubbles": ["...", "..."],
  "candidates": [
    { "word": "...", "confidence": 0.0 }
  ],
  "finalAnswer": "..."
}
```

## 10.8 後追加予定：候補リスト判別

MVP 完成後に、候補リスト判別を追加する予定です。

### 目的

```text
API 利用回数を減らす
判別の安定性を上げる
候補内での一致率を見る
```

### 流れ

```text
1. ゲームで使える候補単語を用意する
2. プレイヤー画像を候補単語のどれに近いか判定する
3. 一致率を出す
4. 一致率が高ければ API を使わない
5. 一致率が低ければ API を使う
```

---

## 10.9 後追加時の判定ルール案

将来的にローカル判別を追加する場合、以下のようにします。

```text
一致率 0.75 以上：ローカル判別を信頼し、API は使わない
一致率 0.75 未満：API へ送信する
```

## 22. 最終方針

> [!IMPORTANT]
> 本プロジェクトの最終方針は、**少ない技術で確実に完成させること**です。  
> AI のズレをゲーム性として活かしつつ、展示で止まらない構成を優先します。

この企画では、以下を正式方針とします。

```text
HTML / CSS / JavaScript / Node.js / Express / SQLite で作る
JavaScript 中心で言語数を抑える
iPad から Windows PC へ画像を送る
ゲーム中も常に □ → □ → □ の進行バーを表示する
しりとり進行は AI 判別結果を優先する
プレイヤー入力は意図として保存する
AI の誤判定やズレをゲームの面白さとして扱う
AI認識演出画面で、AI の見え方を吹き出しとして表示する
AI画像生成中は「絵を描いています...」を表示し、生成元テキストは隠す
AI画像生成は API を使う
候補判別・キャッシュ・ローカル GPU・Cloudflare 化は後追加にする
```

## 23. この仕様の一番大事な考え方

このゲームは、正解を競うゲームではありません。

大事なのは、

```text
プレイヤーが何を思って描いたか
AIが何と判別したか
AIが画像をどう見ているように振る舞ったか
AIの判別によってしりとりがどうズレたか
AIがどんな絵を返したか
次のプレイヤーがどう受け取ったか
```

を見ることです。

つまり、**人間と AI の認識のズレが、そのままゲーム展開になることを楽しむ作品**です。

AI認識演出画面は、そのズレを来場者に見える形で伝えるための重要な演出です。

## 24. 用語解説

### Canvas

ブラウザ上で絵を描くための HTML 機能です。

### Blob

画像などのデータを、ファイルのように扱うための形式です。

### FormData

画像や文字をまとめてサーバーへ送るための形式です。

### Node.js

JavaScript をサーバー側で動かすための実行環境です。

### Express

Node.js で Web サーバーや API を作るための軽量フレームワークです。

### SQLite

ファイル1つで使える軽量データベースです。

### API

外部サービスや別プログラムとやり取りするための窓口です。

### fallback

本命の処理が失敗したときに使う、代替処理のことです。

### キャッシュ

一度作った画像や結果を保存し、次回以降に再利用する仕組みです。

### AI認識演出

AI の本当の内部思考ではなく、AI が画像をどのように認識しているように見えるかを、吹き出しなどで来場者に分かりやすく見せる演出です。
